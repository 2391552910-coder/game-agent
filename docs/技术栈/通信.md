## 本项目中 RobotGateway 和 myAgent2 的通信流程

当前项目中，RobotGateway 和 myAgent2 之间使用的是 HTTP 通信，具体分成两个方向：

1. RobotGateway 主动 POST 玩家事件给 myAgent2。
2. myAgent2 分析完成后，主动 POST 分析完成事件给 RobotGateway。

这两个方向都是普通 HTTP POST 请求，不是 WebSocket，也不是长连接。


### 1. RobotGateway → myAgent2：Webhook 推送玩家事件

RobotGateway 作为调用方，myAgent2 作为接收方。

RobotGateway 在检测到玩家状态或行为变化时，会主动请求 myAgent2 的 Webhook 接口：

```text
POST /webhooks/player-event
```

对应代码入口：

```text
src/api/main.py
src/api/routes/webhooks.py
```

在 `src/api/main.py` 中，webhook 路由被挂载到 `/webhooks` 前缀：

```python
app.include_router(webhooks.router, prefix="/webhooks", tags=["webhooks"])
```

在 `src/api/routes/webhooks.py` 中，具体接口是：

```python
@router.post("/player-event")
async def handle_player_event(event: PlayerEvent, request: Request):
```

所以完整接口地址是：

```text
/webhooks/player-event
```

RobotGateway 请求 myAgent2 时，需要携带 API Key：

```http
X-API-Key: <tenant-api-key>
Content-Type: application/json
```

myAgent2 的认证中间件会读取 `X-API-Key`，验证租户身份，并把租户 ID 写入：

```python
request.state.tenant_id
```

对应代码：

```text
src/api/middleware.py
```


### 2. RobotGateway 推送的数据格式

myAgent2 通过 `PlayerEvent` 模型接收 RobotGateway 推送的数据：

```python
class PlayerEvent(BaseModel):
    user_id: str
    event_type: str
    timestamp: float
    snapshot: dict | None = None
    session_id: str | None = None
    behavior_event: dict | None = None
```

典型的玩家离线事件：

```json
{
  "user_id": "player_001",
  "event_type": "offline",
  "timestamp": 1716000000,
  "snapshot": {
    "level": 28,
    "current_area": "商业区",
    "gold": 1200
  }
}
```

当前支持三类事件：

```text
online
offline
behavior_checkpoint
```


### 3. offline 事件：触发后台分析

当 RobotGateway 推送：

```json
{
  "event_type": "offline"
}
```

myAgent2 会进入 `offline` 分支：

```python
if event.event_type == "offline":
    run_id = await schedule_offline_analysis(
        user_id=event.user_id,
        tenant_id=tenant_id,
        snapshot=event.snapshot,
    )
```

这里不会在 HTTP 请求里直接完成 Agent 分析。

原因是 Agent 分析可能比较耗时，如果 webhook 请求一直等待分析完成，会导致 RobotGateway 长时间阻塞。

所以 myAgent2 的做法是：

1. 收到离线事件。
2. 把分析任务提交给 Prefect 后台流程。
3. 立刻返回 `scheduled` 给 RobotGateway。
4. 后台慢慢执行分析。
5. 分析完成后再回调 RobotGateway。

调度代码：

```text
src/core/scheduler/triggers.py
```

核心逻辑：

```python
flow_run = await run_deployment(
    name="analysis_flow/offline-analysis",
    parameters={
        "user_id": user_id,
        "tenant_id": tenant_id,
        "snapshot": snapshot,
    },
    timeout=0,
)
```

其中：

```python
timeout=0
```

表示只提交任务，不等待任务执行完成。

myAgent2 给 RobotGateway 的即时响应类似：

```json
{
  "status": "scheduled",
  "user_id": "player_001",
  "flow_run_id": "..."
}
```

如果 Redis 中已经存在该玩家的离线分析任务，myAgent2 会去重并返回：

```json
{
  "status": "debounced",
  "user_id": "player_001"
}
```


### 4. online 事件：取消待处理分析

当 RobotGateway 推送：

```json
{
  "event_type": "online"
}
```

myAgent2 会进入 `online` 分支：

```python
elif event.event_type == "online":
    await cancel_offline_analysis(user_id=event.user_id)
```

这表示玩家重新上线了。

myAgent2 会尝试：

1. 删除 Redis 中的离线分析去重 key。
2. 如果 Prefect Flow Run 已经提交，则尝试取消该 Flow Run。

即时响应：

```json
{
  "status": "cancelled",
  "user_id": "player_001"
}
```


### 5. behavior_checkpoint 事件：记录玩家行为

当 RobotGateway 推送：

```json
{
  "user_id": "player_001",
  "event_type": "behavior_checkpoint",
  "timestamp": 1716000000,
  "session_id": "session_001",
  "behavior_event": {
    "type": "quest_abandoned",
    "data": {
      "quest_id": "quest_1001",
      "duration_seconds": 300
    }
  },
  "snapshot": {
    "level": 28
  }
}
```

myAgent2 会把行为事件写入 `session_events` 表。

对应代码：

```python
await _write_behavior_event(
    tenant_id=tenant_id,
    user_id=event.user_id,
    session_id=event.session_id,
    behavior_event=event.behavior_event or {},
    snapshot=event.snapshot,
)
```

注意：

```text
behavior_checkpoint 必须提供 session_id
```

否则 myAgent2 会返回 422。


### 6. myAgent2 后台分析流程

离线分析主流程在：

```text
src/core/scheduler/flows/analysis_flow.py
```

主流程是：

```python
async def analysis_flow(user_id: str, tenant_id: str, snapshot: dict | None = None) -> None:
    if snapshot:
        使用 RobotGateway 推送的 snapshot
    else:
        主动获取玩家快照

    output = await run_agent_task(...)
    await store_result_task(...)
    await send_callback_task(...)
```

可以理解成：

```text
收到离线事件
  → 提交 Prefect 后台任务
  → 获取或复用玩家快照
  → 运行 LangGraph Agent
  → 生成 final_output
  → 存储分析结果
  → 回调 RobotGateway
```

这里的 `send_callback_task` 就是 myAgent2 主动通知 RobotGateway 的步骤。


### 7. myAgent2 → RobotGateway：Callback 回调分析完成事件

myAgent2 分析完成并保存结果后，会主动 POST 给 RobotGateway。

这一步不是 RobotGateway 来查询 myAgent2，而是 myAgent2 主动通知 RobotGateway：

```text
玩家分析完成了，结果在这里。
```

发送代码在：

```text
src/core/integration/robotgateway_callback.py
```

核心逻辑：

```python
async with httpx.AsyncClient(timeout=timeout_seconds, transport=transport) as client:
    response = await client.post(callback_url, json=payload, headers=headers)
    response.raise_for_status()
```

其中：

```python
callback_url
```

来自配置：

```python
settings.robotgateway_callback_url
```

也就是环境变量：

```text
ROBOTGATEWAY_CALLBACK_URL
```

例如：

```env
ROBOTGATEWAY_CALLBACK_URL=http://robotgateway:8080/callbacks/analysis
ROBOTGATEWAY_CALLBACK_API_KEY=secret
ROBOTGATEWAY_CALLBACK_TIMEOUT_SECONDS=10
```


### 8. 回调给 RobotGateway 的数据格式

myAgent2 回调 RobotGateway 时，会发送 `analysis.completed` 事件。

payload 构造代码：

```python
def build_robotgateway_callback_payload(
    *,
    tenant_id: str,
    user_id: str,
    snapshot: dict[str, Any],
    output: dict[str, Any],
) -> dict[str, Any]:
    return {
        "event_type": "analysis.completed",
        "tenant_id": tenant_id,
        "user_id": user_id,
        "timestamp": datetime.now(UTC).isoformat(),
        "snapshot": snapshot,
        "analysis": output,
    }
```

发送给 RobotGateway 的 JSON 类似：

```json
{
  "event_type": "analysis.completed",
  "tenant_id": "tenant_001",
  "user_id": "player_001",
  "timestamp": "2026-05-20T10:30:00+00:00",
  "snapshot": {
    "level": 28,
    "current_area": "商业区"
  },
  "analysis": {
    "player_profile": {
      "engagement_level": "high"
    },
    "recommended_actions": [
      {
        "action_type": "complete_learning_course",
        "priority": "high"
      }
    ]
  }
}
```

回调请求头：

```http
Content-Type: application/json
X-Callback-API-Key: secret
```

其中 `X-Callback-API-Key` 只有在配置了 `ROBOTGATEWAY_CALLBACK_API_KEY` 时才会发送。


### 9. 完整交互时序

```text
玩家离线
  ↓
RobotGateway 检测到玩家离线
  ↓
RobotGateway POST /webhooks/player-event 给 myAgent2
  ↓
myAgent2 校验 X-API-Key
  ↓
myAgent2 识别 event_type = offline
  ↓
myAgent2 使用 Redis 做离线分析去重
  ↓
myAgent2 提交 Prefect analysis_flow/offline-analysis
  ↓
myAgent2 立即返回 scheduled 给 RobotGateway
  ↓
Prefect Worker 后台执行 analysis_flow
  ↓
LangGraph Agent 生成分析结果 final_output
  ↓
myAgent2 存储分析结果
  ↓
myAgent2 POST analysis.completed 给 RobotGateway
  ↓
RobotGateway 接收分析结果并执行后续动作
```


### 10. Webhook 和 Callback 的区别

在这个项目里：

```text
Webhook = RobotGateway 调用 myAgent2
Callback = myAgent2 分析完成后调用 RobotGateway
```

更直观地说：

```text
RobotGateway → myAgent2
  这是 webhook 输入链路。

myAgent2 → RobotGateway
  这是 callback 输出链路。
```

二者本质上都是 HTTP POST。

区别只在于：

```text
谁主动发请求，谁被动接收请求。
```


### 11. 当前实现的通信特点

当前实现具备：

```text
HTTP POST 通信
X-API-Key 租户认证
Redis 限流
Redis 离线分析去重
Prefect 后台异步分析
httpx 主动回调 RobotGateway
回调失败时抛出异常并交给 Prefect 重试
未配置 ROBOTGATEWAY_CALLBACK_URL 时跳过回调
```

当前还没有实现：

```text
Webhook 签名校验
Callback HMAC 签名
请求幂等 ID
回调重放防护
RobotGateway 回调接收端的代码
WebSocket 长连接通信
```

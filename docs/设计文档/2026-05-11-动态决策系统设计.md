# 动态决策系统设计

**日期**：2026-05-11  
**状态**：待实现  
**关联模块**：LangGraph Agent、Webhook、PostgreSQL

---

## 一、背景与目标

现有系统在玩家离线后触发行为分析，输出推荐行动，但缺少以下能力：

- 跨会话的玩家长期记忆（行为画像、目标历史）
- 基于历史执行结果的动态目标调整
- 意图预判（根据本次行为序列推断下次意图）
- 代价收益权衡（判断目标是否值得继续追求）

本设计在现有架构基础上扩展，实现一个**意图预判 + 动态决策闭环**系统，所有分析仍由离线事件触发。

---

## 二、核心功能

### 2.1 在线期间：行为数据积累

玩家在线时，游戏服务器持续推送行为数据。系统完整保存这些数据，不触发任何分析。数据按玩家 ID 和会话 ID 组织存储，作为离线分析的原始素材。

### 2.2 离线后：四步分析流程

#### 第一步：意图预判

分析本次会话的完整行为序列，结合历史数据，判断：

- 玩家这次在线想做什么
- 完成了什么、中途放弃了什么
- 下次上线最可能想继续做什么

#### 第二步：目标校验与决策生成

根据玩家是否已有进行中的目标，走两条路：

**首次（无历史目标）**：
- 基于意图预判生成主目标和执行步骤
- 检查可行性约束：账户余额、消费习惯、游戏内条件
- 不满足约束的目标直接降级或替换

**复盘（有历史目标）**：
- 对比上次目标的完成度和实际代价与预期代价的偏差
- 结合玩家当前账户状态和消费习惯，判断是否值得继续
- 输出三种结论之一：继续推进 / 降低期望 / 切换目标
- 生成新一轮执行步骤

#### 第三步：更新玩家记忆

分析完成后，将新信息沉淀到长期记忆：

- **行为特征**：每次增量更新（消费习惯、活跃偏好、在线时长等）
- **目标记录**：同一目标至少出现 2 次才写入结论，避免偶发行为污染判断

#### 第四步：记录本次决策

将本次生成的目标和步骤持久化，供下次离线复盘对照，同时作为玩家记忆的输入来源。

## 三、玩家记忆体系

系统为每个玩家维护两类长期记忆，随每次离线分析持续积累。

### 3.1 行为画像

记录相对稳定的个人特征，用于判断"玩家能不能、愿不愿意"：

| 字段 | 说明 |
|------|------|
| 消费习惯 | 历史消费频率、单次消费金额区间、是否倾向付费 |
| 活跃偏好 | 偏好的游戏内容类型（社交、战斗、收集等） |
| 活跃时段 | 历史在线时间分布 |
| 平均在线时长 | 每次会话的平均时长 |

### 3.2 目标历史

记录玩家追求过的目标及其结果，用于判断"这个目标对这个玩家是否现实"：

| 字段 | 说明 |
|------|------|
| 目标类型 | 目标的分类标签 |
| 出现次数 | 该目标被推荐或玩家主动追求的次数 |
| 成功次数 | 实际完成的次数 |
| 平均完成代价 | 历史上完成该目标的平均资源消耗 |
| 放弃原因 | 未完成时的主要原因（代价超预期 / 游戏条件不满足 / 意愿不足等） |

---

## 四、代价收益权衡逻辑

这是系统的核心判断环节，采用规则 + LLM 混合方式：

**规则层（量化计算）**：
- 完成度 = 实际结果 / 目标值
- 代价偏差 = 实际代价 / 预期代价

**LLM 层（软性判断）**：
- 结合完成度、代价偏差、账户余额、消费习惯、目标历史，综合判断是否值得继续
- 输出结论：继续 / 降级 / 切换

**判断依据示例**：

| 情况 | 可能结论 |
|------|---------|
| 完成度高、代价在预期内 | 继续推进 |
| 完成度低、但余额充足且历史愿意消费 | 继续推进或降级 |
| 完成度低、代价超预期、历史不愿消费 | 切换目标 |
| 游戏内条件不再满足 | 切换目标 |

## 五、与现有系统的关系

现有节点和表结构基本不变，新能力通过新增节点和扩展上下文输入实现。

### 扩展后的完整流程

```
在线期间：
  游戏服务器 → Webhook 新端点 → session_events 表（只写库）

离线触发：
  intent_inference（新增）
        ↓
  goal_evaluation（新增）
        ↓
  behavior_analysis（现有，扩展输入上下文）
        ↓
  action_reasoning（现有，扩展约束条件）
        ↓
  tracking_update（现有）
        ↓
  memory_update（新增）
```

### 新增内容汇总

| 新增内容 | 类型 | 说明 |
|---------|------|------|
| `session_events` | 数据库表 | 存储在线期间行为序列 |
| `player_intent` | 数据库表 | 存储意图预判结果和当前目标状态 |
| `player_memory` | 数据库表 | 存储行为画像和目标历史 |
| Webhook 新端点 | API | 接收在线期间行为数据，只写库不分析 |
| `intent_inference` | LangGraph 节点 | 意图推断 |
| `goal_evaluation` | LangGraph 节点 | 目标校验 + 决策生成 |
| `memory_update` | LangGraph 节点 | 更新玩家长期记忆 |

## 六、设计原则

- **离线触发不变**：所有分析仍由离线事件驱动，不引入实时分析复杂度
- **渐进积累**：记忆随每次分析自动沉淀，系统判断随时间越来越准
- **非固定模式**：目标和步骤每次都可能调整，不锁定玩家在某条固定路径上
- **约束优先**：可行性约束（余额、游戏条件、消费意愿）在决策生成阶段前置检查，不生成无法执行的目标

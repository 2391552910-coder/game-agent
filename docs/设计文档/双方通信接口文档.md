# myAgent 与 RobotGateway 双方通信接口文档

> 基于当前项目代码整理，日期：2026-06-16。
> 本文用于 myAgent 与 RobotGateway 两方开发、联调、测试时对齐 HTTP 接口、字段含义、必填数据和责任边界。

## 1. 系统职责边界

### 1.1 myAgent 职责

myAgent 是 AI 游戏决策层，负责：

- 接收 RobotGateway 推送的玩家在线、离线、行为检查点事件。
- 对玩家快照、近期行为、历史分析结果、RAG 知识上下文进行分析。
- 通过 LangGraph 决策链路输出可被 RobotGateway 消费的决策结果。
- 决策结果格式为 `skillName + arguments`。
- 将分析结果存入本项目数据库。
- 分析完成后通过 HTTP callback 主动通知 RobotGateway。

myAgent 不负责：

- 不直接连接游戏服协议。
- 不托管玩家 session。
- 不执行账号托管。
- 不承担 RobotGateway 控制面的 HMAC 签名。
- 不直接保证 skill 最终执行成功，最终执行与动作校验由 RobotGateway 负责。

### 1.2 RobotGateway 职责

RobotGateway 是游戏连接和执行层，负责：

- 托管账号和玩家 session。
- 连接游戏服并维护玩家在线状态。
- 在玩家状态变化或行为检查点出现时调用 myAgent webhook。
- 必要时为 myAgent 提供玩家快照查询接口。
- 接收 myAgent 的分析完成 callback。
- 校验 myAgent 输出的 `skillName + arguments` 是否允许执行。
- 将合法 skill 转换为游戏内动作并执行。
- 记录执行结果、失败原因和后续状态。

## 2. 通信链路总览

| 方向 | 调用方 | 接收方 | 接口 | 作用 | 当前代码位置 |
| --- | --- | --- | --- | --- | --- |
| RobotGateway -> myAgent | RobotGateway | myAgent FastAPI | `POST /webhooks/player-event` | 推送在线、离线、行为检查点事件 | `src/api/routes/webhooks.py` |
| myAgent -> RobotGateway | myAgent Prefect Flow | RobotGateway | `GET /players/{user_id}/snapshot` | 离线事件未携带快照时拉取玩家快照 | `src/game_specific/connector.py` |
| myAgent -> RobotGateway | myAgent Prefect Flow | RobotGateway | `POST <ROBOTGATEWAY_CALLBACK_URL>` | 分析完成后回传 AI 决策结果 | `src/core/integration/robotgateway_callback.py` |

主流程：

```text
RobotGateway 推送 offline / behavior_checkpoint
  -> myAgent POST /webhooks/player-event
  -> myAgent 根据 X-API-Key 识别 tenant_id
  -> offline 事件触发 Prefect deployment analysis_flow/offline-analysis
  -> analysis_flow 使用请求中的 snapshot，或向 RobotGateway 拉取 snapshot
  -> LangGraph Agent 进行意图识别、目标评估、行为分析、行动推理
  -> PostgreSQL 写入 analysis_results / player_intent / player_memory / action_tracking
  -> myAgent POST callback 到 RobotGateway
  -> RobotGateway 校验并执行 recommended_actions 中的 skillName + arguments
```

## 3. 环境变量与配置

### 3.1 myAgent 侧配置

| 配置项 | 必填 | 说明 |
| --- | --- | --- |
| `GAME_DATA_SOURCE` | 建议 | 设置为 `robotgateway` 时，myAgent 通过 HTTP 从 RobotGateway 拉取快照 |
| `ROBOTGATEWAY_BASE_URL` | 条件必填 | myAgent 拉取快照时使用，例如 `http://127.0.0.1:9000` |
| `ROBOTGATEWAY_SNAPSHOT_API_KEY` | 可选 | myAgent 调用 RobotGateway 快照接口时放入请求头 `X-API-Key` |
| `ROBOTGATEWAY_SNAPSHOT_TIMEOUT_SECONDS` | 可选 | 快照接口超时时间，默认 10 秒 |
| `ROBOTGATEWAY_CALLBACK_URL` | 建议 | myAgent 分析完成后回调 RobotGateway 的完整 URL |
| `ROBOTGATEWAY_CALLBACK_API_KEY` | 可选 | myAgent callback 时放入请求头 `X-Callback-API-Key` |
| `ROBOTGATEWAY_CALLBACK_TIMEOUT_SECONDS` | 可选 | callback 超时时间，默认 10 秒 |
| `PREFECT_API_URL` | 本地联调必填 | FastAPI 提交 `analysis_flow/offline-analysis` deployment 时使用 |

如果 `ROBOTGATEWAY_CALLBACK_URL` 未配置，myAgent 会跳过 callback，不把它视为分析失败。

### 3.2 RobotGateway 侧需要保存的 myAgent 配置

| 配置项 | 必填 | 说明 |
| --- | --- | --- |
| `MYAGENT_BASE_URL` | 必填 | myAgent API 地址，例如 `http://127.0.0.1:8000` |
| `MYAGENT_PLAYER_EVENT_PATH` | 必填 | 固定为 `/webhooks/player-event` |
| `MYAGENT_API_KEY` | 必填 | 调用 myAgent 时放入 `X-API-Key`，用于识别租户 |
| `ROBOTGATEWAY_CALLBACK_URL` | 建议 | 提供给 myAgent 配置的 callback 接收地址 |
| `ROBOTGATEWAY_SNAPSHOT_API_KEY` | 可选 | 如果 RobotGateway 快照接口需要鉴权，应与 myAgent 配置一致 |
| `ROBOTGATEWAY_CALLBACK_API_KEY` | 可选 | 如果 RobotGateway callback 接收端需要鉴权，应与 myAgent 配置一致 |

## 4. RobotGateway 调用 myAgent：玩家事件 Webhook

### 4.1 接口定义

```http
POST /webhooks/player-event
Host: <myagent-host>:8000
Content-Type: application/json
X-API-Key: <tenant-api-key>
```

完整示例：

```text
POST http://127.0.0.1:8000/webhooks/player-event
```

### 4.2 请求头

| Header | 必填 | 说明 |
| --- | --- | --- |
| `Content-Type: application/json` | 必填 | 请求体为 JSON |
| `X-API-Key` | 必填 | myAgent 用它查询 `tenants.api_key`，认证通过后写入 `request.state.tenant_id` |

认证失败：

| 场景 | HTTP 状态码 | 响应 |
| --- | --- | --- |
| 缺少 `X-API-Key` | 401 | `{"detail":"缺少X-API-Key"}` |
| API Key 无效或租户停用 | 401 | `{"detail":"无效的 API Key"}` |

### 4.3 请求体字段

当前 myAgent 接收模型为 `PlayerEvent`。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `user_id` | string | 必填 | 玩家唯一 ID。myAgent 后续分析、存储、callback 都以该字段识别玩家 |
| `event_type` | string | 必填 | 事件类型。当前支持 `online`、`offline`、`behavior_checkpoint` |
| `timestamp` | number | 必填 | 事件发生时间戳。建议使用 Unix timestamp 秒，允许小数 |
| `snapshot` | object/null | 可选 | 玩家快照。`offline` 时建议携带；`behavior_checkpoint` 可携带当前局部状态 |
| `session_id` | string/null | 条件必填 | `behavior_checkpoint` 事件必填，用于写入 `session_events.session_id` |
| `behavior_event` | object/null | 可选 | 在线行为事件详情。`behavior_checkpoint` 时建议携带 |

### 4.4 `event_type=offline`

用途：玩家离线后触发 AI 分析。

RobotGateway 需要提供的数据：

| 字段 | 是否必须 | 建议 |
| --- | --- | --- |
| `user_id` | 必须 | 使用 RobotGateway 和游戏服一致的玩家 ID |
| `event_type` | 必须 | 固定为 `offline` |
| `timestamp` | 必须 | 玩家离线时间 |
| `snapshot` | 强烈建议 | 建议直接传完整快照，可减少 myAgent 再向 RobotGateway 发起一次 `GET /players/{user_id}/snapshot` |

请求示例：

```json
{
  "user_id": "player_001",
  "event_type": "offline",
  "timestamp": 1781577600.123,
  "snapshot": {
    "user_id": "player_001",
    "level": 28,
    "player_name": "测试玩家001",
    "current_area": "main_city",
    "position": {
      "x": 12.5,
      "y": 0,
      "z": -8.2
    },
    "currencies": {
      "gold": 1200,
      "diamond": 35
    },
    "online_today_hours": 1.4,
    "main_quest_progress": 42,
    "available_skills": [
      "observe_state",
      "move_to",
      "stop_move",
      "jump",
      "play_action"
    ],
    "game_specific": {
      "current_quest": "quest_1001",
      "unlocked_actions": ["wave", "sit", "interact"]
    }
  }
}
```

成功响应：

```json
{
  "status": "scheduled",
  "user_id": "player_001",
  "flow_run_id": "36e77f2b-2af6-48ad-93ac-8e46a7f42f9e"
}
```

如果同一个 `user_id` 的离线分析已在去重窗口内提交，myAgent 返回：

```json
{
  "status": "debounced",
  "user_id": "player_001"
}
```

处理规则：

- `offline` 事件会调用 `schedule_offline_analysis()`。
- myAgent 使用 Redis key `debounce:{user_id}` 做去重。
- 去重窗口由 `offline_trigger_minutes` 控制。
- 成功调度时，myAgent 提交 Prefect Deployment：`analysis_flow/offline-analysis`。
- 如果请求体带 `snapshot`，Prefect Flow 直接使用该快照。
- 如果请求体未带 `snapshot`，Prefect Flow 会调用 RobotGateway 快照接口。

### 4.5 `event_type=online`

用途：玩家重新上线时取消待处理离线分析。

RobotGateway 需要提供的数据：

| 字段 | 是否必须 | 建议 |
| --- | --- | --- |
| `user_id` | 必须 | 与 offline 事件一致 |
| `event_type` | 必须 | 固定为 `online` |
| `timestamp` | 必须 | 玩家上线时间 |
| `snapshot` | 可选 | 当前代码不依赖该字段 |

请求示例：

```json
{
  "user_id": "player_001",
  "event_type": "online",
  "timestamp": 1781577800.456
}
```

成功响应：

```json
{
  "status": "cancelled",
  "user_id": "player_001"
}
```

处理规则：

- myAgent 删除 Redis 去重 key。
- 如果去重 key 中保存的是真实 Prefect flow_run_id，myAgent 尝试取消该 Flow Run。
- 如果 Flow Run 已完成或无法取消，日志记录 warning，不影响接口响应。

### 4.6 `event_type=behavior_checkpoint`

用途：RobotGateway 在玩家在线期间把关键行为写入 myAgent，用于后续意图识别、上下文管理和对话/行为状态追踪。

RobotGateway 需要提供的数据：

| 字段 | 是否必须 | 建议 |
| --- | --- | --- |
| `user_id` | 必须 | 玩家唯一 ID |
| `event_type` | 必须 | 固定为 `behavior_checkpoint` |
| `timestamp` | 必须 | 行为发生时间 |
| `session_id` | 必须 | 当前玩家 session ID |
| `behavior_event` | 建议 | 具体行为内容 |
| `snapshot` | 可选 | 当前行为发生时的局部或完整快照 |

请求示例：

```json
{
  "user_id": "player_001",
  "event_type": "behavior_checkpoint",
  "timestamp": 1781577900.789,
  "session_id": "session_20260616_001",
  "behavior_event": {
    "type": "quest_progress",
    "data": {
      "quest_id": "quest_1001",
      "progress_before": 40,
      "progress_after": 42,
      "area": "main_city"
    }
  },
  "snapshot": {
    "level": 28,
    "main_quest_progress": 42,
    "current_area": "main_city"
  }
}
```

成功响应：

```json
{
  "status": "recorded",
  "user_id": "player_001"
}
```

缺少 `session_id` 时响应：

```json
{
  "detail": "behavior_checkpoint 事件必须提供 session_id"
}
```

HTTP 状态码为 422。

写库规则：

| 入库字段 | 来源 |
| --- | --- |
| `tenant_id` | `X-API-Key` 认证后解析 |
| `user_id` | 请求体 `user_id` |
| `session_id` | 请求体 `session_id` |
| `event_type` | `behavior_event.type`，缺省为 `unknown` |
| `event_data` | `behavior_event.data` |
| `snapshot` | 请求体 `snapshot` |

### 4.7 不支持的事件类型

请求示例：

```json
{
  "user_id": "player_001",
  "event_type": "unknown_event",
  "timestamp": 1781578000
}
```

响应：

```json
{
  "detail": "未知事件类型: unknown_event"
}
```

HTTP 状态码为 400。

## 5. myAgent 调用 RobotGateway：拉取玩家快照

### 5.1 触发条件

当满足以下条件时，myAgent 会调用 RobotGateway 快照接口：

- Prefect `analysis_flow` 收到 `offline` 分析任务。
- Flow 入参 `snapshot` 为空。
- `GAME_DATA_SOURCE=robotgateway`，或配置了 `ROBOTGATEWAY_BASE_URL`。

如果 RobotGateway 在 `offline` webhook 中已经传入有效 `snapshot`，myAgent 不会再拉取快照。

### 5.2 接口定义

```http
GET /players/{user_id}/snapshot
Host: <robotgateway-host>:9000
X-API-Key: <optional-snapshot-api-key>
```

完整示例：

```text
GET http://127.0.0.1:9000/players/player_001/snapshot
```

`user_id` 会进行 URL encode。

### 5.3 请求头

| Header | 必填 | 说明 |
| --- | --- | --- |
| `X-API-Key` | 可选 | 仅当 myAgent 配置 `ROBOTGATEWAY_SNAPSHOT_API_KEY` 时发送 |

### 5.4 RobotGateway 需要返回的数据

RobotGateway 可以直接返回 snapshot object：

```json
{
  "user_id": "player_001",
  "level": 28,
  "current_area": "main_city",
  "position": {
    "x": 12.5,
    "y": 0,
    "z": -8.2
  },
  "currencies": {
    "gold": 1200,
    "diamond": 35
  },
  "main_quest_progress": 42,
  "available_skills": [
    "observe_state",
    "move_to",
    "stop_move",
    "jump",
    "play_action"
  ],
  "game_specific": {
    "current_quest": "quest_1001",
    "unlocked_actions": ["wave", "sit", "interact"]
  }
}
```

也可以返回带 `snapshot` 包装的 object：

```json
{
  "snapshot": {
    "user_id": "player_001",
    "level": 28,
    "current_area": "main_city",
    "position": {
      "x": 12.5,
      "y": 0,
      "z": -8.2
    },
    "currencies": {
      "gold": 1200
    }
  }
}
```

myAgent 当前解析规则：

- 响应必须是 JSON object。
- 如果顶层存在 `snapshot` 且 `snapshot` 是 object，则使用 `payload.snapshot`。
- 否则使用整个响应 object 作为 snapshot。
- 如果 snapshot 中没有 `user_id`，myAgent 会自动补充当前请求的 `user_id`。

### 5.5 建议的 snapshot 字段

myAgent 对 snapshot 是开放结构，不要求所有字段固定。但是为了让意图识别、目标评估、RAG 查询和 skill 决策更可靠，RobotGateway 建议提供以下数据。

| 字段 | 类型 | 建议级别 | 用途 |
| --- | --- | --- | --- |
| `user_id` | string | 必填 | 玩家身份识别 |
| `player_name` | string | 建议 | 行为分析文本上下文 |
| `level` | number | 建议 | 玩家阶段判断 |
| `vip_level` | number | 可选 | 付费层级判断 |
| `current_area` | string | 建议 | 位置、场景、RAG 查询 |
| `position` | object | 建议 | 当前位置，建议包含 `x/y/z` |
| `currencies` | object | 建议 | 资源状态判断 |
| `inventory` | array/object | 可选 | 背包、道具、材料判断 |
| `main_quest_progress` | number | 建议 | 主线目标判断 |
| `current_quest` | string/object | 建议 | 当前任务判断 |
| `available_quests` | array | 可选 | 后续目标选择 |
| `available_skills` | array | 建议 | RobotGateway 当前允许的 skill 列表 |
| `unlocked_actions` | array | 建议 | `play_action.arguments.action` 可选枚举 |
| `online_today_hours` | number | 建议 | 活跃度判断 |
| `play_hours` | number | 建议 | 长期行为画像 |
| `session_minutes` | number | 可选 | 当前会话时长 |
| `pvp_rating` | number | 可选 | PVP 玩家判断 |
| `stats` | object | 可选 | 统一指标集合，action tracking 可读取其中的数值 |
| `bottlenecks` | array | 可选 | 当前卡点 |
| `game_specific` | object | 建议 | 游戏特定字段，允许双方按游戏扩展 |

坐标和动作枚举建议由 RobotGateway 或知识库提供。myAgent 在无法确认坐标或动作枚举时，应降级输出 `observe_state`，不应编造。

### 5.6 失败处理

| 场景 | myAgent 行为 |
| --- | --- |
| RobotGateway 返回非 2xx | 抛出 `DatabaseError`，Prefect `fetch-snapshot` task 最多重试 2 次 |
| 请求超时 | 抛出 `DatabaseError`，Prefect task 重试 |
| 响应不是 JSON | 抛出 `DatabaseError`，Prefect task 重试 |
| 响应不是 object | 抛出 `DatabaseError`，Prefect task 重试 |
| 响应中没有有效 snapshot object | 抛出 `DatabaseError`，Prefect task 重试 |

## 6. myAgent 调用 RobotGateway：分析完成 Callback

### 6.1 触发条件

当以下步骤都成功后，myAgent 会发送 callback：

```text
analysis_flow
  -> 获取 snapshot
  -> run_agent_task 执行 LangGraph
  -> store_result_task 写入 analysis_results
  -> send_callback_task 发送 RobotGateway callback
```

只有分析结果已经持久化成功，才会进入 callback。

### 6.2 接口定义

callback URL 由 myAgent 配置项 `ROBOTGATEWAY_CALLBACK_URL` 决定。

示例：

```http
POST /callbacks/analysis
Host: <robotgateway-host>:9000
Content-Type: application/json
X-Callback-API-Key: <optional-callback-api-key>
```

完整示例：

```text
POST http://127.0.0.1:9000/callbacks/analysis
```

### 6.3 请求头

| Header | 必填 | 说明 |
| --- | --- | --- |
| `Content-Type: application/json` | 必填 | myAgent 固定发送 |
| `X-Callback-API-Key` | 可选 | 仅当 myAgent 配置 `ROBOTGATEWAY_CALLBACK_API_KEY` 时发送 |

### 6.4 请求体字段

当前 callback payload 由 `build_robotgateway_callback_payload()` 生成。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `event_type` | string | 必填 | 固定为 `analysis.completed` |
| `tenant_id` | string | 必填 | myAgent 认证解析出的租户 ID |
| `user_id` | string | 必填 | 玩家 ID |
| `timestamp` | string | 必填 | myAgent 发送 callback 的 UTC ISO 时间 |
| `snapshot` | object | 必填 | 本次分析使用的快照 |
| `analysis` | object | 必填 | LangGraph Agent 输出的最终分析结果 |

完整示例：

```json
{
  "event_type": "analysis.completed",
  "tenant_id": "tenant_001",
  "user_id": "player_001",
  "timestamp": "2026-06-16T08:00:00.000000+00:00",
  "snapshot": {
    "user_id": "player_001",
    "level": 28,
    "current_area": "main_city",
    "position": {
      "x": 12.5,
      "y": 0,
      "z": -8.2
    }
  },
  "analysis": {
    "player_profile": {
      "playstyle": "任务推进型玩家",
      "current_goal": ["推进主线任务", "熟悉当前区域"],
      "bottlenecks": ["主线进度停留在 42%"],
      "engagement_level": "medium"
    },
    "recommended_actions": [
      {
        "skillName": "observe_state",
        "schemaVersion": "v1",
        "arguments": {},
        "reason": "当前缺少可确认的目标坐标，先观察状态以获取更准确的场景信息",
        "priority": "high",
        "ttlMs": 30000,
        "goal_metric": null,
        "goal_value": null,
        "expected_hours": null
      }
    ]
  }
}
```

注意：当前代码字段名是 `analysis`，不是 `analysis_result`。

### 6.5 `analysis.player_profile`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `playstyle` | string | 必填 | 玩家行为风格 |
| `current_goal` | array[string] | 必填 | 推断出的当前目标 |
| `bottlenecks` | array[string] | 必填 | 当前瓶颈 |
| `engagement_level` | string | 必填 | 活跃度，可取 `high`、`medium`、`low` |

### 6.6 `analysis.recommended_actions`

`recommended_actions` 是 RobotGateway 最需要消费的数据。每一项是一个 AiRobotGateway skill 控制请求。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `skillName` | string | 必填 | RobotGateway skill 名称 |
| `schemaVersion` | string | 必填 | 当前固定为 `v1` |
| `arguments` | object | 必填 | skill 参数 |
| `reason` | string | 必填 | myAgent 推荐该动作的原因 |
| `priority` | string | 必填 | 优先级，可取 `high`、`medium`、`low` |
| `ttlMs` | number/null | 可选 | 请求有效期，单位毫秒；默认 30000 |
| `goal_metric` | string/null | 可选 | 追踪完成情况的 snapshot 指标名 |
| `goal_value` | number/null | 可选 | 达到该值视为目标完成 |
| `expected_hours` | number/null | 可选 | 预计完成小时数 |

RobotGateway 执行时主要使用：

```json
{
  "skillName": "move_to",
  "arguments": {
    "target": {
      "x": 10,
      "y": 0,
      "z": 20
    },
    "stopDistance": 1.5
  }
}
```

`reason`、`priority`、`ttlMs` 可用于调度、排序、过期判断和日志排查。`goal_metric`、`goal_value`、`expected_hours` 主要供 myAgent 后续行动追踪使用，RobotGateway 可以记录但不必作为执行参数。

## 7. 第一阶段允许的 Skill

当前 `RecommendedAction.skillName` 只允许以下五类。

| skillName | arguments 要求 | 说明 |
| --- | --- | --- |
| `observe_state` | `{}` | 观察当前状态，不执行复杂动作 |
| `move_to` | `{"target":{"x":number,"y":number,"z":number},"stopDistance":number}` | 移动到目标坐标；`target.x/y/z` 必须是数字 |
| `stop_move` | `{}` | 停止移动 |
| `jump` | `{}` | 跳跃 |
| `play_action` | `{"action":string}` | 播放或触发已知动作；`action` 必填 |

### 7.1 `observe_state`

```json
{
  "skillName": "observe_state",
  "schemaVersion": "v1",
  "arguments": {},
  "reason": "需要先确认当前场景和可交互对象",
  "priority": "high",
  "ttlMs": 30000
}
```

### 7.2 `move_to`

```json
{
  "skillName": "move_to",
  "schemaVersion": "v1",
  "arguments": {
    "target": {
      "x": 10.0,
      "y": 0.0,
      "z": 20.0
    },
    "stopDistance": 1.5
  },
  "reason": "移动到任务 NPC 附近继续主线",
  "priority": "high",
  "ttlMs": 30000
}
```

校验规则：

- `arguments.target` 必须存在。
- `target.x`、`target.y`、`target.z` 必须是数字。
- 布尔值不视为合法数字。
- `stopDistance` 当前不是 Pydantic 强制字段，但建议 RobotGateway 支持。

### 7.3 `stop_move`

```json
{
  "skillName": "stop_move",
  "schemaVersion": "v1",
  "arguments": {},
  "reason": "当前位置可能已到达目标区域，先停止移动避免偏离",
  "priority": "medium",
  "ttlMs": 30000
}
```

### 7.4 `jump`

```json
{
  "skillName": "jump",
  "schemaVersion": "v1",
  "arguments": {},
  "reason": "尝试越过低障碍物",
  "priority": "low",
  "ttlMs": 30000
}
```

### 7.5 `play_action`

```json
{
  "skillName": "play_action",
  "schemaVersion": "v1",
  "arguments": {
    "action": "interact"
  },
  "reason": "当前目标需要与场景对象交互",
  "priority": "high",
  "ttlMs": 30000
}
```

校验规则：

- `arguments.action` 必填。
- `action` 的可选值应由 RobotGateway snapshot、RAG 知识库或双方约定枚举提供。
- myAgent 不应输出聊天、交易、抽奖、领奖、战斗、排行榜或底层协议动作，除非双方产品边界明确要求。

## 8. 双方必须提供的数据清单

### 8.1 RobotGateway 调 myAgent 时必须提供

| 数据 | 必须接口 | 说明 |
| --- | --- | --- |
| `X-API-Key` | `POST /webhooks/player-event` | myAgent 用于租户识别和鉴权 |
| `user_id` | `POST /webhooks/player-event` | 玩家唯一 ID |
| `event_type` | `POST /webhooks/player-event` | 当前支持 `online`、`offline`、`behavior_checkpoint` |
| `timestamp` | `POST /webhooks/player-event` | 事件时间 |
| `session_id` | `behavior_checkpoint` | 行为检查点必填 |

### 8.2 RobotGateway 建议提供给 myAgent 的数据

| 数据 | 提供方式 | 作用 |
| --- | --- | --- |
| 完整 `snapshot` | `offline` webhook 或 snapshot 接口 | 提高决策准确性，减少一次 HTTP 拉取 |
| 位置坐标 | snapshot | 让 myAgent 可以安全输出 `move_to` |
| 可用动作枚举 | snapshot / RAG | 让 myAgent 可以安全输出 `play_action` |
| 当前任务和场景 | snapshot | 用于目标评估与 RAG 查询 |
| 资源、等级、进度 | snapshot | 用于意图识别和行动追踪 |
| 在线行为事件 | `behavior_checkpoint` | 用于上下文管理、对话状态追踪、玩家意图更新 |

### 8.3 myAgent callback 必须提供给 RobotGateway

| 数据 | 字段位置 | 说明 |
| --- | --- | --- |
| 回调事件类型 | `event_type` | 固定 `analysis.completed` |
| 租户 ID | `tenant_id` | myAgent 内部租户 ID |
| 玩家 ID | `user_id` | RobotGateway 需要映射到对应 session 或账号 |
| 回调时间 | `timestamp` | UTC ISO 时间 |
| 分析所用快照 | `snapshot` | 便于 RobotGateway 审计和复现决策 |
| 玩家画像 | `analysis.player_profile` | 辅助调度和日志 |
| 推荐动作 | `analysis.recommended_actions` | RobotGateway 执行层主要消费的数据 |

### 8.4 RobotGateway 执行 recommended_actions 时应读取

| 字段 | 必须读取 | 用途 |
| --- | --- | --- |
| `skillName` | 是 | 选择 RobotGateway skill |
| `arguments` | 是 | 作为 skill 参数 |
| `schemaVersion` | 建议 | 参数版本兼容 |
| `priority` | 建议 | 多动作排序 |
| `ttlMs` | 建议 | 丢弃过期动作 |
| `reason` | 建议 | 日志和可观测性 |

RobotGateway 不应把 HTTP 2xx 当成 skill 执行成功。HTTP 2xx 只表示 callback 已接收。真正执行是否成功，应看 RobotGateway 自己的 skill 校验和执行结果。

## 9. 幂等、并发与多玩家处理

### 9.1 多个不同 `user_id` 同时发送

RobotGateway 可以并发向 myAgent 发送多个不同玩家的 webhook。

myAgent 当前处理方式：

- 鉴权按 `X-API-Key` 解析出 `tenant_id`。
- 离线分析去重 key 是 `debounce:{user_id}`。
- 不同 `user_id` 的离线事件互不覆盖。
- 相同 `user_id` 在去重窗口内重复发送 `offline`，后续请求会返回 `debounced`。
- Prefect 并发能力受部署、worker 和 `max_concurrent_analyses` 等配置影响。

注意：当前 Redis 去重 key 只包含 `user_id`，不包含 `tenant_id`。如果不同租户可能出现相同 `user_id`，建议后续调整为 `debounce:{tenant_id}:{user_id}`，或确保 RobotGateway 传入的 `user_id` 在全局范围唯一。

### 9.2 callback 幂等建议

当前 callback payload 没有单独的业务幂等 ID。

RobotGateway 建议使用以下组合作为幂等键：

```text
event_type + tenant_id + user_id + timestamp
```

如果 RobotGateway 需要更强幂等性，建议后续双方扩展：

```json
{
  "analysis_id": "analysis_result_id",
  "flow_run_id": "prefect_flow_run_id"
}
```

当前代码尚未在 callback payload 中包含这两个字段。

## 10. 错误处理约定

| 链路 | 场景 | 当前行为 |
| --- | --- | --- |
| RobotGateway -> myAgent webhook | 缺少 API Key | myAgent 返回 401 |
| RobotGateway -> myAgent webhook | API Key 无效 | myAgent 返回 401 |
| RobotGateway -> myAgent webhook | 请求过于频繁 | myAgent 返回 429 |
| RobotGateway -> myAgent webhook | 未知事件类型 | myAgent 返回 400 |
| RobotGateway -> myAgent webhook | `behavior_checkpoint` 缺少 `session_id` | myAgent 返回 422 |
| myAgent -> RobotGateway snapshot | 非 2xx、超时、JSON 无效 | Prefect task 抛错并重试 |
| myAgent -> RobotGateway callback | 未配置 callback URL | 跳过 callback，不视为失败 |
| myAgent -> RobotGateway callback | 非 2xx、超时、网络异常 | 抛出 `RobotGatewayCallbackError`，Prefect task 重试 |

## 11. 联调检查清单

### 11.1 RobotGateway 侧

- 已配置 myAgent 地址：`http://127.0.0.1:8000` 或实际部署地址。
- 已保存有效 `X-API-Key`。
- 能调用 `POST /webhooks/player-event`。
- `offline` 事件能携带完整 `snapshot`，或已提供 `GET /players/{user_id}/snapshot`。
- 已实现并开放 callback 接收端，例如 `POST /callbacks/analysis`。
- callback 接收端能校验 `X-Callback-API-Key`，如果双方启用该鉴权。
- callback 接收端能解析 `analysis.recommended_actions`。
- RobotGateway 对 `skillName + arguments` 做白名单校验、参数校验和执行结果记录。

### 11.2 myAgent 侧

- FastAPI 服务已启动。
- PostgreSQL、Redis 等依赖服务已启动。
- 租户表 `tenants` 中已有与 RobotGateway 使用的 `X-API-Key` 对应的活跃租户。
- Prefect Server 已启动。
- `analysis_flow/offline-analysis` deployment 已注册或通过 `scripts/run_analysis_flow_serve.cmd` serve。
- `GAME_DATA_SOURCE=robotgateway` 和 `ROBOTGATEWAY_BASE_URL` 配置正确，若需要从 RobotGateway 拉快照。
- `ROBOTGATEWAY_CALLBACK_URL` 配置正确，若需要分析完成后主动通知 RobotGateway。
- LLM、Embedding、RAG 相关配置可用，避免 LangGraph 分析节点失败。

## 12. 最小联调样例

### 12.1 RobotGateway 发送 offline

```powershell
$body = @{
  user_id = "player_001"
  event_type = "offline"
  timestamp = 1781577600
  snapshot = @{
    user_id = "player_001"
    level = 28
    current_area = "main_city"
    position = @{
      x = 12.5
      y = 0
      z = -8.2
    }
    available_skills = @("observe_state", "move_to", "stop_move", "jump", "play_action")
    game_specific = @{
      unlocked_actions = @("interact", "wave", "sit")
    }
  }
} | ConvertTo-Json -Depth 10

Invoke-RestMethod `
  -Method Post `
  -Uri "http://127.0.0.1:8000/webhooks/player-event" `
  -Headers @{ "X-API-Key" = "<tenant-api-key>" } `
  -ContentType "application/json" `
  -Body $body
```

### 12.2 RobotGateway 提供 snapshot

myAgent 会请求：

```http
GET http://127.0.0.1:9000/players/player_001/snapshot
X-API-Key: <optional-snapshot-api-key>
```

RobotGateway 返回：

```json
{
  "snapshot": {
    "user_id": "player_001",
    "level": 28,
    "current_area": "main_city",
    "position": {
      "x": 12.5,
      "y": 0,
      "z": -8.2
    },
    "available_skills": [
      "observe_state",
      "move_to",
      "stop_move",
      "jump",
      "play_action"
    ]
  }
}
```

### 12.3 myAgent callback 到 RobotGateway

RobotGateway 应接收：

```json
{
  "event_type": "analysis.completed",
  "tenant_id": "tenant_001",
  "user_id": "player_001",
  "timestamp": "2026-06-16T08:00:00.000000+00:00",
  "snapshot": {
    "user_id": "player_001",
    "level": 28
  },
  "analysis": {
    "player_profile": {
      "playstyle": "任务推进型玩家",
      "current_goal": ["推进主线任务"],
      "bottlenecks": [],
      "engagement_level": "medium"
    },
    "recommended_actions": [
      {
        "skillName": "observe_state",
        "schemaVersion": "v1",
        "arguments": {},
        "reason": "缺少可确认坐标，先观察状态",
        "priority": "high",
        "ttlMs": 30000
      }
    ]
  }
}
```

RobotGateway 只要成功接收、鉴权、持久化或入队，建议返回任意 2xx。非 2xx 会被 myAgent 视为 callback 失败并触发 Prefect 重试。

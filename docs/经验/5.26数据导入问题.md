**可以导入 RAG，但不能直接把 `D:\Projects\myAgent2\game_docs\游戏场景数据` 整个目录丢进去。**  
这个目录本质上是一个混合工程包：`SG-Client` 约 51GB、7.6 万多个文件，里面大量是 Unity 图片、模型、`.meta`、SDK、NDK、二进制和第三方源码；直接导入会非常慢、成本高，而且会严重污染检索结果。

真正适合进 RAG 的是这些子集：

- `Excel\Datas`：最有价值，约 116 个 `.xlsx` 配置表，包含场景、区域、传送、触发器、NPC 路径等结构化数据。
- `Excel\Datas\PathFinding`：`SceneEntry.xlsx`、`SceneExit.xlsx`、`SceneLink.xlsx`，很适合做场景连通关系。
- `SG_Proto`：可作为接口/行为语义补充，但不是主要场景知识。
- `SG-Client\Unity\Assets\Bundles\Scene` 下的 `.unity` 场景文件：可以选取性解析，但不建议第一批导入，Unity YAML 噪声比较大。

我抽样看了几个关键表，质量是可用的：

- `AreaConfig.xlsx`：区域多边形、最低/最高高度、`SceneId`
- `SceneTriggerConfig.xlsx`：触发器、进入/退出动作、人数限制
- `SceneTriggerAction.xlsx`：触发行为类型和参数
- `SceneEntry.xlsx` / `SceneExit.xlsx` / `SceneLink.xlsx`：场景入口、出口、场景跳转连接
- `NPCAIPathNew.xlsx`：NPC 初始坐标和 NPC ID
- `PointConfig.xlsx`：传送点名、地图点、实际坐标
- `NavigationConfig.xlsx`：导航目标和界面跳转

但当前项目里的 [scripts/test_game_data_import.py](D:/Projects/myAgent2/scripts/test_game_data_import.py) 不能直接用，因为它读取的是：

```python
game_docs / "游戏场景数据.md"
```

而现在实际存在的是目录：

```text
game_docs\游戏场景数据\
```

不是 `游戏场景数据.md` 文件。

建议的导入方式是：**先把 Excel 配置表转换成 RAG 友好的文本/JSONL，再调用 `rag.ainsert(...)`。** 不要按原始 `.xlsx` 入库。每一行最好转成类似这样的文本：

```text
[场景连通关系]
来源表: PathFinding/SceneLink.xlsx
FromSceneId=7, ToSceneId=8, LinkId=1, FromExitId=1, ToEntryId=2。
含义: 场景 7 可以通过出口 1 连接到场景 8 的入口 2。
```

或者：

```text
[场景触发器]
来源表: SceneTriggerConfig.xlsx
Id=1，备注=坐位，进入行为=1，退出行为=3，只在客户端触发=False，限制人数=True，最大人数=1。
```

还需要特别注意一点：你现在的 RAG 查询构建逻辑在 [src/core/agents/nodes.py](D:/Projects/myAgent2/src/core/agents/nodes.py:115) 主要从玩家快照里提取**文本值**，不太使用数字 ID。  
所以导入时不能只保留 `SceneId=7`、`NPCId=1` 这种 ID，最好把中文备注、场景名、区域名、功能名、触发含义也拼进去，否则检索命中会偏弱。

我的判断：

- **可用**：`Excel\Datas` 转文本后非常适合导入 LightRAG。
- **暂不建议**：整包导入 `SG-Client`。
- **需要改造**：现有导入脚本要从读取单个 Markdown，改成读取 Excel/结构化表并生成文档块。
- **优先导入范围**：`AreaConfig`、`NavigationConfig`、`SceneTrigger*`、`SceneRiver*`、`SceneGameObjectConfigId`、`PathFinding/*`、`PointConfig`、`TransportConfig`、`NPC*`、`CoffeeShopArea`、`RoleTransformDataConfig`。

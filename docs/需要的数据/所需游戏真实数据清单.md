# myAgent2 所需游戏真实数据清单

为了让 myAgent2（大模型）能够输出可直接执行的动作序列（包含精准坐标、枚举值），并做出合理的行为权衡（去哪、玩什么、花多少钱），需要从游戏获取以下真实数据，整理后导入 LightRAG 知识库。

---

## 1. 地图与建筑坐标数据
用于大模型输出 `move_to` 行动时的 `target(x,y,z)`。

**需要提取的内容：**
- **地点名称**（如：商业区入口、健身房大门、射击场、咖啡厅）。
- **中心坐标或入口坐标** (X, Y, Z)。
- **建筑 ID**（如进入建筑需要传参，如 `gym_01`）。
- **地点描述与连通性**（可选，如"健身房在商业区内"）。

**最终文本示例格式：**
> - 商业区入口：坐标 (120, 0, 85)。
> - 健身房大门：坐标 (134, 0, 92)，建筑 ID 为 `gym_01`。
> - 射击场：坐标 (150, 0, 80)。

---

## 2. 动作枚举白名单数据
用于大模型输出 `action_steps` 时的 `skill` 和 `params`。

**需要提取的内容：**
- **HostingGateway 支持的 Skill 列表**（如 `move_to`, `play_action`）。
- **每个 Skill 需要的参数格式**。
- **具体动作枚举值**（如 `play_action` 支持哪些动作：`wave`, `sit`, `dance`, `start_shooting`）。
- **动作的使用限制**（例如：打靶动作只能在射击场使用）。

**最终文本示例格式：**
> - `move_to`：移动技能，参数需包含 `target` 坐标(x,y,z) 和 `speed`(可选 walk 或 run)。
> - `play_action`：执行基础动作技能，参数需包含 `name`，可选枚举值有：
>   - `wave`：挥手，无限制。
>   - `sit`：坐下，无限制。
>   - `start_shooting`：开始射击，必须在射击场坐标范围内使用。

---

## 3. 游戏活动与玩法数据
用于大模型进行策略权衡（玩什么最适合当前玩家）。

**需要提取的内容：**
- **活动名称与业务 ID**（如：射箭 `act_archery`、打枪 `act_shooting`）。
- **触发地点坐标 / 建筑 ID**。
- **参与条件**（如：需达到 LV5，或需要持有弓箭道具）。
- **消耗成本**（如：每次消耗 50 金币 或 10 体力）。
- **收益与产出**（如：奖励 100 竞技积分）。
- **耗时评估**（如：单局约 2 分钟）。
- **适合人群 / 玩法定位**（用于 LLM 匹配行为画像，如"适合在线时间短的玩家"）。

**最终文本示例格式：**
> - 射击活动（ID: `act_shooting`）：位于射击场 (150,0,80)。每次参与消耗 50 金币，单局耗时约 2 分钟。产出大量竞技积分，可用于兑换稀有装扮。适合在线时间短、消费能力强的玩家。
> - 射箭活动（ID: `act_archery`）：位于体育馆 (200,0,100)。无金币消耗但需要消耗 10 体力，产出敏捷经验。适合倾向于免费获取数值成长的玩家。

---

## 4. 经济系统（货币与商品）数据
用于大模型进行开销评估和购买决策。

**需要提取的内容：**
- **货币种类**（如：金币、积分、钻石）及获取方式摘要。
- **核心商品或服务的价格表**（如：健身房月卡、咖啡、射击门票）。
- **积分兑换规则**（如：消费 1 金币得 1 积分）。

**最终文本示例格式：**
> 游戏主要使用"金币"和"竞技积分"。"金币"可通过在线时间获取，"竞技积分"通过参与射击等活动获取。
> 价格表：
> - 健身房月卡：200 金币（ID: `item_gym_month`）。
> - 咖啡：15 金币（ID: `item_coffee`）。

---

## 交付说明

以上数据不需要严格格式要求。请用**清晰的自然语言（如上述示例）**写入 `.txt` 或 `.md` 文件或其他数据格式，放入 `docs/knowledge/` 目录下（或直接交给 LLM），然后通过导入脚本存入 LightRAG 知识库即可。大模型在检索时会自动理解这些文本背后的实体与关系。

通用协议

这部分是两边共用的传输、鉴权、ID、幂等和格式规则。

Header 说明
X-AppId调用方 AppId。Gateway 和 LLM 方向分开配置，不共用密钥。
X-TimestampMs毫秒时间戳字符串，参与签名，同一次重试必须不变。
X-RequestIdHTTP 请求幂等 ID，同一次重试必须不变。
X-SignatureHMAC-SHA256 hex，不带前缀。
 
signature = hmac_sha256(appSecret,
  method + "\n" +
  path + "\n" +
  timestampMs + "\n" +
  requestId + "\n" +
  sha256(rawBody).hexLower()
).hexLower()
规则 约束
传输生产必须 HTTPS；内网联调可按部署配置例外使用 HTTP。
Body只收 UTF-8 JSON，不收 form / multipart / plain text。
大小双方都应配置 body size limit，超限返回请求级错误。
业务 ID全部按 opaque string 处理，即使底层是 long 也不能用 JSON number。
枚举严格字面量匹配，不做大小写兼容、别名兼容或 trim。
整数occurredAtMs / sceneId / waitMs 等只能用普通十进制整数写法。
未知字段严格拒绝，不静默忽略。
ID 角色 规则
traceId链路追踪Gateway 生成，可在同一链路里复用，不是幂等键。
gatewayId实例标识只用于日志和来源识别，不参与幂等。
eventId事件幂等Gateway 全局唯一，LLM 只按 eventId + bodySha256 去重。
decisionId决策幂等LLM 全局唯一，不按 session 复用。
decisionLeaseId决策许可一次性、只消费一次。
skillCallId技能执行标识Gateway 生成，全局唯一。
sessionId会话标识一次托管生命周期只用一次，不复用。
accountId / roleId业务标识仍然按 string 传输，不传 number。
请求级错误： bad_request / signature_invalid / timestamp_expired / internal_error 四个 code。
请求级错误不进业务处理。
Gateway -> LLM 事件 API

入口：POST /api/gateway/events。每次只发单个 event，不用 batch。

Envelope 字段 说明
traceId链路 ID。
gatewayIdGateway 实例 ID。
contractVersion固定 llm-gateway-http-v1。
event单个事件对象。
eventType 决策 lease payload 说明
session_started必填session托管开始，LLM 做第一轮决策。
skill_finished必填session + skill技能进入终态，LLM 做下一轮决策。
observation_updated必填session + observation新的观察和下一轮决策机会。
session_stopped不允许session + stop会话终态，不再决策。
session 字段 类型 说明
sessionIdstring一次托管生命周期一个 ID，不复用。
accountIdstring长期保留，但不赋予账号管理权限。
roleIdstring当前被托管角色 ID。
sceneIdinteger场景配置 ID，不能是字符串或小数。
statestringRunning / Stopped / Failed。
positionobject{x,y,z}，都必须是有限 number。
controllableboolean当前是否可操作。
stop.reason session.state 说明
admin_stopStopped后台/人工停止。
stop_hosting_requestedStoppedLLM 自己要求停止。
player_onlineStopped玩家本人上线。
server_kickedStopped服务器踢下线。
gateway_shutdownStoppedGateway 关闭或重启。
runtime_errorFailedGateway 内部错误。
observation.reason 说明
wait_completed上一次 wait 到期。
state_changed关键状态变化。
事件响应： LLM 只能返回 accepted 或 duplicate。
accepted 代表可靠接收，不是“HTTP 到了但还没处理”。
同一 eventId + 不同 body 视为协议错误，返回 400 bad_request。 
{
  "status": "accepted",
  "eventId": "evt-001"
}
{
  "status": "duplicate",
  "eventId": "evt-001"
}

完整字段、错误和重试规则：llm-gateway-event-api.md

LLM -> Gateway 决策 API

入口：POST /api/v1/hosting/llm/decision。一次决策只允许一个 action。

Request 字段 说明
contractVersion固定 llm-gateway-http-v1。
decisionIdLLM 幂等 ID，全局唯一。
decisionLeaseIdGateway 发放的一次性决策许可。
actioncall_skill / wait / stop_hosting。
skillName仅 call_skill 时允许。
schemaVersion仅 call_skill 时允许。
argumentscall_skill 必填 object；wait 可省略或传 {}。
action 约束
call_skill必须带 canonical skillName、schemaVersion 和 arguments。
waitwaitMs 默认 3000，最小 1000，最大 10000。
stop_hosting结束本次托管，优先级最高。
Decision Response 说明
statusaccepted / rejected。
reasonaccepted 时固定 ok；rejected 时返回固定枚举。
skillCallId仅 call_skill 被接受时返回。
sessionId可选，只用于可解析到 session 时的辅助返回。
rejected reason 说明
lease_expired旧 lease、已失效、已消费、已被替代或会话终态。
schema_invalid字段、结构、枚举或参数契约不合法。
skill_not_allowed技能在账号/角色/场景/权限/配置维度不允许。
state_not_allowed当前会话状态不允许这次动作。
skill_in_progress当前运行中的 skill 不允许被打断或替换。
idempotency_key_conflict同一个 decisionId 对应了不同 lease 或不同 body。
lease 规则：一张 lease 只消费一次；被消费后不能用同一张 lease 改参数重发。
429 不消费 lease，500 只有在消费前失败时才不消费。
LLM 收到 accepted 后只等 Gateway 后续事件，不主动轮询。

明确不做
  • 不使用批量事件 events[]。
  • 不在事件里传 goal、availableSkills、skillArgumentHints、runningSkill、lastSkillResult、interruptedSkill、LLM token、message。
  • 不提供 skill_started、heartbeat、decision_rejected、lease_revoked 事件。
  • 不做 /capabilities runtime 接口。
  • /decision 不带 traceId / sessionId / sourceEventId / stateVersion。
  • /decision 不支持 confidence / ttlMs / message / reason 这类额外字段。
  • 不提供 cancel_skill action。
  • 不把版本号、build 号塞进 runtime JSON body，只写日志或部署元数据。
后续单开
  • 首批 LLM 可调用 skill 清单。
  • 每个 skill 的 arguments / schemaVersion / skill_finished.reason / TTL / 可打断/抢占规则。
  • 自动射击、移动中打枪等复合行为，先作为 canonical skill 讨论。
  • 只读 Query 的 queryType / arguments / result / reason / 缓存和新鲜度。
  • 可选的运维 /health 实现细节。

根据项目架构设计，各数据库的职责如下：

## 📊 数据存储架构

### 1. **PostgreSQL** (`POSTGRES_DSN`)
**存储内容**：业务核心数据
- 租户信息（多租户隔离）
- 用户配额管理（Token 限额）
- 分析任务记录（任务状态、执行时间）
- 分析结果持久化（行为画像、推荐行动）
- 用户认证与授权数据

### 2. **Neo4j** (`NEO4J_URI`)
**存储内容**：知识图谱数据
- 游戏实体关系（地点、活动、商品之间的关联）
- 玩家行为模式图谱
- 游戏规则知识图谱
- 实体属性与关系边

### 3. **Redis** (`REDIS_URL`)
**存储内容**：缓存与状态
- LLM 响应缓存（减少重复调用）
- 文档分块缓存（`text_chunks`）
- 完整文档缓存（`full_docs`）
- 实体与关系缓存（`full_entities`, `full_relations`）
- 文档状态存储（`doc_status`）
- 分布式去重（防止重复分析）
- 限流计数与状态

### 4. **Milvus** (`MILVUS_URI`)
**存储内容**：向量数据
- 文档语义向量（用于相似度检索）
- 实体嵌入向量
- 查询向量索引
- 支持 HNSW 索引 + 余弦相似度

### 5. **Game DB** (`GAME_DB_DSN`)
**存储内容**：游戏原始数据（只读）
- 玩家快照（PlayerSnapshot）
- 玩家历史行为记录
- 游戏内事件日志
- 玩家属性与状态

### 6. **RAG Working Dir** (`RAG_WORKING_DIR`)
**存储内容**：LightRAG 本地元数据
- 文档索引元信息
- 检索策略配置
- 工作区隔离数据

## 🔄 数据流转示意图

```
游戏服务器 ──► Game DB（玩家快照/行为）
                  │
                  ▼
            myAgent 分析引擎
                  │
    ┌─────────────┼─────────────┐
    ▼             ▼             ▼
 PostgreSQL    LightRAG      Redis
 (业务数据)    (知识库)       (缓存)
    │             │             │
    │       ┌─────┴─────┐       │
    │       ▼           ▼       │
    │    Milvus     Neo4j       │
    │  (向量)      (图谱)       │
    └───────────────────────────┘
```

### 核心数据流向：
1. **导入阶段**：游戏文档 → LightRAG → Milvus（向量）+ Neo4j（图谱）+ Redis（缓存）
2. **分析阶段**：Game DB（玩家数据）→ Agent 推理 → PostgreSQL（存储结果）
3. **检索阶段**：用户查询 → Redis（快速缓存）→ Milvus/Neo4j（深度检索）→ LLM 生成

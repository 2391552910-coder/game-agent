# Test Spec: AI 离线托管中转层

## 状态
- 日期：2026-04-16
- 适用计划：`.omx/plans/prd-ai-offline-hosting-gateway.md`
- 实现边界：独立项目测试，不修改当前 Unity 客户端工程
- 技术栈：不限定

## 测试目标
验证 AI 托管中转层能在技术栈中立、独立项目边界下，完成 `v0.1` 单账号基础行为闭环，并为 `v1.0` 多账号并发稳定性提供可执行验收标准。

## 测试原则
- 所有测试只验证独立项目和游戏服交互，不要求改 Unity 客户端。
- 大模型输出必须经 skill schema 和中转层校验后才能触发协议发送。
- 每条成功和失败路径都必须有审计日志。
- 高复杂行为必须保持不可用。

## 测试环境前置
- 至少一个 v0.1 测试账号。
- v1.0 所需的多个测试账号。
- 业务方指定测试场景。
- 独立中转层可连接目标游戏服或测试服。
- 协议适配器已具备登录、进场景、移动、跑、跳、基础动作能力。
- 审计日志可查询。
- 协议契约 source of truth、协议契约版本和独立项目可消费产物已明确。

- 验收 owner。

## 协议契约测试
### PCT-001 协议契约产物来源确认
步骤：
1. 记录协议 source of truth。
2. 记录独立项目消费的协议产物。
3. 记录协议契约版本。

期望：
- 产物来源明确。
- 版本号明确。
- owner 信息明确。
- 不依赖 Unity 客户端运行时。

### PCT-002 协议契约一致性
步骤：
1. 使用独立项目消费的协议产物生成或加载登录、进场景、角色命令所需消息。
2. 与 source of truth 对比消息名、字段、方向和必要枚举。

期望：
- 必需消息字段一致。
- 变更能被检测出来。
- 不一致时阻止 v0.1 / v1.0 验收。

### PCT-003 禁止运行时客户端耦合
步骤：
1. 检查独立项目运行依赖。
2. 检查是否引用 Unity Runtime、FUI、客户端热更程序集或当前 Unity 客户端仓库。

期望：
- 不存在运行时客户端耦合。
- 当前 Unity 客户端无修改。

## v0.1 测试用例
### V01-001 托管授权建立
步骤：
1. 使用测试账号创建托管会话。
2. 中转层生成或接收托管授权。
3. 查询会话状态。

期望：
- 会话状态为 authorized 或等价状态。
- 大模型不可读取明文账号密码。
- 审计记录包含授权创建结果。

### V01-002 登录成功
步骤：
1. 使用授权会话发起登录。
2. 等待游戏服返回登录结果。
3. 查询会话状态。

期望：
- 会话状态为 logged_in 或等价状态。
- 登录失败时不会继续执行后续 skill。
- 审计记录包含登录请求摘要和结果。

### V01-003 进入指定场景
步骤：
1. 登录后由网关 bootstrap 流程进入指定场景。
2. 等待服务器确认角色进入场景。
3. 调用 `observe_state`。

期望：
- `observe_state.sceneId` 等于指定场景。
- `observe_state.position` 有有效值。
- 未进入场景前调用移动类 skill 会被拒绝。
- `enter_scene` 不作为 v0.1 默认模型可调用 skill 暴露。

### V01-004 状态观察
步骤：
1. 调用 `observe_state`。
2. 检查返回字段。

期望：
- 返回 `sessionId / roleId / sceneId / position / movementState / controllable / availableSkills`。
- 不返回无关敏感信息。
- 返回内容足以支撑移动、跑、跳、基础动作决策。

### V01-005 普通移动
步骤：
1. 记录初始位置。
2. 调用 `move_to`，`speedMode=walk`。
3. 等待移动结果。
4. 再次调用 `observe_state`。

期望：
- 角色位置发生符合预期的变化。
- 通过服务器可观测状态确认移动，不要求复刻 Unity 客户端表现层细节。
- 移动过程中未超过限频。
- 审计记录包含 skill 入参、校验结果、协议发送结果、最终位置。

### V01-006 跑步移动
步骤：
1. 记录初始位置。
2. 调用 `move_to`，`speedMode=run`。
3. 等待移动结果。
4. 查询最终状态。

期望：
- 角色完成跑步语义移动。
- 跑步仍经过同一 skill schema 和限频校验。
- 非法 speedMode 被拒绝。

### V01-007 停止移动
步骤：
1. 启动一次移动。
2. 移动过程中调用 `stop_move`。
3. 查询最终状态。

期望：
- 角色停止移动。
- `movementState` 变为 idle 或等价状态。
- 审计记录包含停止动作。

### V01-008 跳跃闭环
步骤：
1. 确认角色可控且在场景内。
2. 调用 `jump`。
3. 等待跳跃结束。
4. 查询状态。

期望：
- 跳跃开始和结束都有可观测结果。
- 跳跃期间重复调用 `jump` 会被限频或拒绝。
- 不会出现无限跳跃循环。

### V01-009 基础动作白名单
步骤：
1. 调用 `play_action`，传入白名单动作。
2. 调用 `play_action`，传入非白名单动作。

期望：
- 白名单动作可执行。
- 非白名单动作被拒绝。
- 被拒绝动作不发送真实协议。

### V01-010 非目标能力拒绝
步骤：
1. 尝试调用聊天、任务、收益、背包、交易、付费、战斗相关 skill。

期望：
- 中转层返回 unsupported 或 forbidden。
- 不发送真实协议。
- 审计记录标记为 non_goal_rejected。

### V01-011 非法参数拒绝
步骤：
1. 对 `move_to` 传入缺失 target 的参数。
2. 对 `jump` 传入无关字段。
3. 对 `play_action` 传入非法 actionName。

期望：
- schema 校验失败。
- 不发送真实协议。
- 审计记录包含拒绝原因。

## v1.0 测试用例
### V10-001 多账号并发登录
步骤：
1. 使用业务方指定数量的测试账号同时创建托管会话。
2. 执行登录。
3. 查询全部会话状态。

期望：
- 所有成功账号进入 logged_in 或等价状态。
- 单个账号失败不影响其他账号。
- 有每账号独立错误计数。
- 并发账号数满足 `V10_CONCURRENT_ACCOUNTS`。

### V10-002 并发基础行为循环
步骤：
1. 多账号同时执行 observe -> move -> run -> jump -> action -> idle 循环。
2. 持续业务方指定时长。

期望：
- 不出现系统性掉线。
- 不出现明显乱发协议。
- 各账号审计日志完整。
- 运行时长满足 `V10_RUN_DURATION`。
- 非法真实协议发送次数满足 `V10_ILLEGAL_PROTOCOL_SENDS`。

### V10-003 心跳与重连
步骤：
1. 模拟单账号连接短暂中断。
2. 观察重连策略。
3. 继续执行基础 skill。

期望：
- 受影响账号进入 reconnecting 或等价状态。
- 重连成功后可继续运行。
- 重连失败超过阈值时仅熔断该账号。

### V10-004 单账号异常隔离
步骤：
1. 对一个账号注入非法状态或连续失败。
2. 其他账号继续执行正常行为。

期望：
- 异常账号被暂停或熔断。
- 其他账号不受影响。
- 审计记录能定位异常账号。

### V10-005 乱发协议防护
步骤：
1. 尝试在未登录状态调用移动。
2. 尝试在未进场景状态调用跳跃。
3. 尝试在不可控状态调用移动。
4. 尝试高频重复 jump。

期望：
- 所有非法状态动作被拒绝。
- 不发送真实协议。
- 连续异常触发熔断。

### V10-006 审计回放
步骤：
1. 选择一个账号的一段运行记录。
2. 按时间顺序回放 observation、decision、skill call、validation、protocol、response、state。

期望：
- 可还原一次完整托管过程。
- 可区分 AI 决策、网关拒绝、协议发送、服务器响应。

## 观测指标
### v0.1
- 登录成功率。
- 进入指定场景成功率。
- skill 成功率。
- 非法 skill 拒绝率。
- 审计覆盖率。

### v1.0
- 并发会话数。
- 会话存活时长。
- 掉线次数。
- 重连成功率。
- 每账号错误数。
- 熔断次数。
- 协议拒绝次数。
- 平均决策间隔。

## 验收证据包
每次验收必须提供：

- 协议契约版本与一致性测试结果。
- traceId、sessionId、skillCallId 关联字段。
- 每账号时序日志。
- skill 调用与拒绝原因统计。
- 协议发送、拒发、服务器拒绝、服务器成功响应计数。
- 会话状态迁移记录。
- 熔断触发与恢复记录。
- v0.1 单账号闭环摘要。
- v1.0 并发运行摘要。

## 通过标准
### v0.1 Gate
- PCT-001 到 PCT-003 全部通过。
- V01-001 到 V01-011 全部通过。
- 当前 Unity 客户端无任何修改。
- 审计日志可证明每条 skill 的执行或拒绝原因。
- 指标满足 `V01_*` 参数表。

### v1.0 Gate
- PCT-001 到 PCT-003 全部通过。
- V10-001 到 V10-006 全部通过。
- 并发数量和运行时长达到业务方指定值。
- 单账号异常不会造成全局故障。
- 审计日志支持按账号回放。
- 指标满足 `V10_*` 参数表。

## 不通过条件
- 大模型可以直接发送裸协议。
- 非白名单 skill 可以绕过中转层。
- 未登录、未进场景或不可控状态仍能发送动作协议。
- 高复杂行为在 `v0.1` 或 `v1.0` 被开放。
- 当前 Unity 客户端工程被修改。

# 平台总览

面向管理层和业务方，说明 myAgent 平台解决什么问题、如何运作、如何接入。

---

## 平台定位

myAgent 是一个 **游戏玩家行为自动分析与推荐平台**。它解决的核心问题是：

> 游戏运营团队需要为每个玩家提供个性化的行为建议（如推荐活动、挽回流失、引导消费），但人工分析不可能覆盖数万甚至数百万玩家。

平台的工作方式：

1. **游戏服务器**在玩家离线时发送一个 Webhook 通知
2. **平台自动获取**该玩家的当前数据（等级、资源、行为统计等）
3. **AI 分析引擎**结合游戏规则知识库，生成个性化的行为画像和推荐行动
4. **游戏服务器**查询分析结果，用于推送消息、活动推荐、客服干预等

整个过程全自动，从玩家离线到分析结果就绪，通常在 **30 秒以内**。

## 多租户隔离

平台采用多租户架构，每个游戏（或游戏服务器）是一个独立租户：

| 维度 | 隔离方式 | 说明 |
|------|---------|------|
| 身份认证 | 独立 API Key | 每个租户分配唯一的 `gap_` 前缀密钥 |
| 分析数据 | 租户 ID 过滤 | 所有查询自动按租户隔离，无法跨租户访问 |
| 知识库 | 工作空间隔离 | 每个游戏的游戏文档独立存储，互不干扰 |
| 配额 | 独立月度配额 | 每个租户独立的 Token 用量统计和限制 |
| 速率限制 | 租户 + IP 维度 | 防止单个租户占用过多资源 |

## 接入流程

游戏团队接入平台只需 **三步**：

### 第一步：注册租户

```
POST /api/v1/tenants/register
{"user_id": "your-game-identifier"}

返回: {"tenant_id": "...", "api_key": "gap_xxxxxxxx", ...}
```

### 第二步：实现数据接口

在游戏服务器端实现一个函数，返回玩家当前状态的字典数据。字段名和格式在 `connector.py` 中定义。

### 第三步：发送玩家事件

在玩家离线和上线时，向平台发送 Webhook 通知：

```
POST /webhooks/player-event
Headers: X-API-Key: gap_xxxxxxxx
Body: {"user_id": "player123", "event_type": "offline", "timestamp": 1744100000.0}
```

三步完成后，平台即可开始自动分析。详细步骤见 [对接指南](integration-guide.md)。

## 平台价值

| 指标 | 传统人工 | myAgent 平台 |
|------|---------|-------------|
| 分析覆盖 | 仅高价值玩家（前 1-5%） | 全量玩家（100%） |
| 分析延迟 | 小时 ~ 天级 | 秒级（自动触发） |
| 推荐依据 | 运营经验 | 游戏规则知识库 + 数据驱动 |
| 一致性 | 因人而异 | 统一模型，风格一致 |
| 运营成本 | 需要专职分析团队 | 自动化，仅需维护知识库 |

## 关键概念

| 概念 | 说明 |
|------|------|
| **租户 (Tenant)** | 一个游戏或一个游戏服务器，通过 API Key 标识 |
| **快照 (Snapshot)** | 玩家当前状态的数据字典，由游戏方提供 |
| **分析结果 (Analysis Result)** | 平台输出的行为画像 + 推荐行动 |
| **知识库 (Knowledge Base)** | 游戏规则文档，用于增强推荐精度 |
| **去重 (Debounce)** | 玩家反复上下线时，只执行一次分析 |
| **配额 (Quota)** | 每个租户的月度 Token 使用量限制 |
